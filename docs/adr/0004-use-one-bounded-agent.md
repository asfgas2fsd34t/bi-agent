# 第一版使用单个有界 Agent

第一版将分类、澄清、语义检索、候选生成、有限修复和洞察表达组织为一个具有明确状态与终止条件的 Agent，而不拆成 SQL、图表和洞察等多个自治 Agent。多 Agent 能提供角色分工与潜在并行性，但当前流程共享同一分析上下文且关键步骤大多顺序依赖；单个有界 Agent 更容易控制成本、追踪状态、复现失败并执行最多两次修复的限制。

## Consequences

- 工作流节点可以专业化，但共享同一个 Agent 状态和 AnalysisRun，不以“Agent 角色”包装普通函数。
- 不采用开放式 ReAct 循环；每条分支、重试条件和终止状态都必须明确。
- 只有出现不同权限边界、独立上下文所有权或可度量的并行收益时，才重新评估多 Agent。
