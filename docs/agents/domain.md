# 领域文档

工程技能在探索代码前，应读取根目录的 `CONTEXT.md` 和 `docs/adr/` 中与当前任务相关的 ADR。

如果这些文件尚不存在，直接继续，不需要提示缺失。`domain-modeling` 会在产生真实领域决策时按需创建它们。

## 文档结构

本项目采用单上下文结构：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── ...
```

根目录 `CONTEXT.md` 保存整个项目共享的领域词汇和边界。`docs/adr/` 保存对系统具有长期影响且难以轻易逆转的架构决策。

## 领域词汇

Issue、规格、代码、测试和设计文档应统一使用 `CONTEXT.md` 定义的领域术语。避免使用被词汇表明确排除的同义词。

如果需要的概念尚未出现在词汇表中，应先判断它是临时实现术语还是真实领域缺口。真实领域缺口交由 `domain-modeling` 澄清并记录。

## ADR 冲突

如果计划与现有 ADR 冲突，必须明确指出冲突及重新讨论的理由，不能静默覆盖既有决策。
